## 1. Agent 编排

| 名称 | 类型 | 作用 |
|---|---|---|
| `Agent` | 抽象基类（ABC） | 所有编排策略的统一抽象：对外契约 `run` / `run_stream` / `run_events` / `add_hook`。子类只需实现 `run_events`（编排循环的唯一实现），`run` / `run_stream` 由基类统一作为事件流消费者实现 |
| `ReactAgent` | 类（`Agent` 子类） | ReAct（Reason→Act→Observe）循环编排器，单 Agent 单轮往复；支持注入记忆、工具白名单、并行工具、技能注册表、模型重试 |
| `PlanExecuteAgent` | 类（`Agent` 子类） | 规划-执行策略：先规划（分解步骤清单）再逐步执行（复用 `ReactAgent` 子循环），最后整合为最终答案 |
| `Orchestrator` | 类（`Agent` 子类） | 多 Agent 协作编排（主管-工人模式）：主管拆分任务并分派给多个工人 Agent，各工人独立完成后汇总为最终答案 |

### 1.1 `Agent`

```python
class Agent(ABC):
    def __init__(self, provider: ModelProvider, hooks: list[HookFn] | None = None) -> None: ...
    def add_hook(self, hook: HookFn) -> None: ...
    def run(self, user_input: str) -> str: ...
    def run_stream(self, user_input: str) -> Iterator[str]: ...
    @abstractmethod
    def run_events(self, user_input: str, *, stream: bool = False) -> Iterator[AgentEvent]: ...
```

- `run`：执行一次请求，收敛 `FinalAnswerEvent` 返回最终答案；未收敛返回兜底文案。
- `run_stream`：执行一次请求，流式产出文本增量（内部走 `run_events(stream=True)`）。
- `run_events`：编排循环的唯一实现（子类必须提供），逐步产出事件。
- `add_hook`：注册事件回调（on_step 语义）。

### 1.2 `ReactAgent`

```python
ReactAgent(
    provider: ModelProvider,
    memory: Memory | MemoryManager | None = None,
    retrieve_every_iteration: bool = False,
    skill_registry: SkillRegistry | None = None,
    hooks: list[HookFn] | None = None,
    max_retries: int = 0,
    tools: list[str] | None = None,
    parallel_tool_calls: bool = False,
    tool_registry: ToolRegistry | None = None,
)
```

| 参数 | 作用 |
|---|---|
| `provider` | 模型提供者实例（必填） |
| `memory` | 记忆实现；`None` 时默认 `ShortTermMemory(max_message=20)` + 内置系统提示；传入 `MemoryManager` 启用长期记忆检索注入 |
| `retrieve_every_iteration` | `True` 时每轮 ReAct 都注入长期记忆检索，`False` 仅首轮注入 |
| `skill_registry` | 技能注册表；非 `None` 时登记给 `load_skill` 工具，并在默认系统提示中列出可用技能 |
| `hooks` | 事件回调列表 |
| `max_retries` | 模型调用失败重试次数；仅对 `retryable=True` 的 `ProviderError` 指数退避重试，默认 0 不重试 |
| `tools` | 工具白名单（工具名列表）；`None` 表示全量可用 |
| `parallel_tool_calls` | `True` 时同一轮多个工具调用并行执行（默认串行） |
| `tool_registry` | 工具注册表实例（`ToolRegistry`）；`None` 时使用模块级默认注册表（向后兼容）。注入后 Agent 持有隔离的工具集与技能集，同一进程内多个 Agent 互不干扰 |

### 1.3 `PlanExecuteAgent`

```python
PlanExecuteAgent(
    provider: ModelProvider,
    memory: Memory | MemoryManager | None = None,
    retrieve_every_iteration: bool = False,
    skill_registry: SkillRegistry | None = None,
    max_steps: int = 5,
    hooks: list[HookFn] | None = None,
    tool_registry: ToolRegistry | None = None,
)
```

- `max_steps`：规划步骤数量上限，超出截断。
- 规划器输出无法解析时退化为单步骤直接执行原任务。
- 内部持有 `executor`（一个 `ReactAgent`），逐步执行规划出的步骤。
- `tool_registry`：工具注册表实例（`ToolRegistry`）；`None` 时使用模块级默认注册表（向后兼容），并透传给内部执行器。

### 1.4 `Orchestrator`

```python
Orchestrator(
    supervisor: Agent,
    workers: dict[str, Agent],
    parallel: bool = False,
    hooks: list[HookFn] | None = None,
)
```

- `supervisor`：主管 Agent，负责拆分与分派（其 provider 同时用于结果汇总）。
- `workers`：工人名 → 工人 Agent 的映射，不能为空。
- `parallel`：`True` 时各工人子任务并行执行（要求工人线程安全），`False` 串行。
- 分派输出无法解析或指派未登记工人时，退化为把原任务派给全部工人。

## 2. 事件流与回调

| 名称 | 类型 | 作用 |
|---|---|---|
| `AgentEvent` | dataclass（基类） | 所有事件的基类，携带 `seq` / `iteration` / `timestamp` / `type` 公共字段 |
| `StepStartEvent` | dataclass | 一轮 ReAct 迭代开始 |
| `TextDeltaEvent` | dataclass | 流式模式下的文本增量（`delta` 字段） |
| `ModelMessageEvent` | dataclass | 模型本轮完整响应（`content` / `tool_calls` / `usage`） |
| `ToolCallStartEvent` | dataclass | 单个工具执行前（`tool_call_id` / `name` / `arguments`） |
| `ToolCallEndEvent` | dataclass | 单个工具执行结束（`result` / `truncated` / `error`） |
| `FinalAnswerEvent` | dataclass | 循环收敛，给出最终答案（`content`） |
| `LoopAbortEvent` | dataclass | 循环被中止（达到最大轮数），携带 `reason` |
| `PlanGeneratedEvent` | dataclass | `PlanExecuteAgent` 规划器产出的步骤清单（`steps`） |
| `PlanStepStartEvent` | dataclass | `PlanExecuteAgent` 开始执行某步骤（`index` / `step`） |
| `PlanStepEndEvent` | dataclass | `PlanExecuteAgent` 某步骤执行完成（`result`） |
| `TeamPlanGeneratedEvent` | dataclass | `Orchestrator` 主管产出的分派清单（`assignments`） |
| `AgentHandoffEvent` | dataclass | `Orchestrator` 把子任务移交给工人（`worker` / `task`） |
| `SubtaskEndEvent` | dataclass | `Orchestrator` 某子任务执行完成（`result`） |
| `HookFn` | 类型别名 | 事件回调签名：`Callable[[AgentEvent], AgentEvent | None]`，返回 `None` 表示不修改，返回事件对象表示替换 |
| `JsonlEventSink` | 类 | 事件落盘器，把事件流逐条序列化为 JSONL（可作上下文管理器） |
| `jsonl_hook` | 函数 | 构造把事件写入 `JsonlEventSink` 的落盘回调（纯观察） |
| `load_jsonl_events` | 函数 | 回放 JSONL 事件文件，返回事件字典列表 |

`AgentEvent` 及所有子类均提供 `to_dict()`，把事件（含嵌套 dataclass）序列化为纯 JSON 字典，供落盘与离线回放。

## 3. 记忆

| 名称 | 类型 | 作用 |
|---|---|---|
| `Memory` | 抽象基类（ABC） | 记忆抽象接口：`add_message` / `get_messages` / `clear` 三方法 |
| `MemoryEntry` | dataclass（frozen） | 长期记忆中的一条记录（`id` / `role` / `content` / `timestamp` / `distance`） |
| `Session` | dataclass（frozen） | 会话快照（`id` / `created_at` / `model` / `messages` / `metadata`），用于断线恢复 |
| `ShortTermMemory` | 类（`Memory` 子类） | 短期记忆：最近 N 条消息滑窗 + 可选 token 预算裁剪 |
| `LongTermMemory` | 类（`Memory` 子类） | 长期记忆：基于向量语义检索；可注入 embedding 与自定义 `VectorStore` 后端 |
| `MemoryManager` | 类 | 组合器：统一管理短期 + 长期记忆，负责检索注入、上下文预算、会话摘要/画像沉淀与会话快照 |
| `EmbeddingFn` | 类型别名 | `Callable[[list[str]], list[list[float]]]`，自定义向量化函数契约 |
| `ProfileHookFn` | 类型别名 | `Callable[[list[dict], dict | None], dict | None]`，用户画像更新钩子契约 |
| `VectorStore` | 协议（Protocol） | 向量存储后端协议：`add` / `get` / `query` / `delete` |
| `ChromaVectorStore` | 类 | `VectorStore` 协议的默认实现，包装 chromadb Collection |
| `ContextBuilder` | 协议（Protocol） | 上下文构建器协议：`build_context(query)`；`Memory` 基类提供默认实现（返回 `get_messages()`），`MemoryManager` 覆写为检索注入 + 预算裁剪 |

### 3.1 `Memory`

```python
class Memory(ABC):
    @abstractmethod
    def add_message(self, message: dict[str, Any]) -> None: ...
    def build_context(self, query: str = "") -> list[dict[str, Any]]: ...
    @abstractmethod
    def get_messages(self, limit: int | None = None) -> list[dict[str, Any]]: ...
    @abstractmethod
    def clear(self) -> None: ...
```

自定义记忆只需继承 `Memory` 实现 `add_message` / `get_messages` / `clear` 三方法，即可
`ReactAgent(memory=...)` 注入；`build_context` 有默认实现（返回 `get_messages()`），
需要检索注入时覆写它即可（即实现 `ContextBuilder` 协议，`MemoryManager` 亦如此）。

### 3.2 `ShortTermMemory`

```python
ShortTermMemory(max_tokens: int | None = None, max_message: int | None = 20)
```

- `max_message`：保留的最大消息条数（超出移除最早）。
- `max_tokens`：保留的最大 token 预算（超出从最旧移除，至少保留最新一条）。

### 3.3 `LongTermMemory`

```python
LongTermMemory(
    vector_db: Any = None,          # chromadb.Client；与 store 二选一
    collection_name: str = "memory",
    recency_weight: float = 0.0,
    max_entries: int | None = None,
    dedupe: bool = False,
    embedding_function: EmbeddingFn | None = None,
    relevance_threshold: float | None = None,
    mmr_lambda: float | None = None,
    store: VectorStore | None = None,
)
```

除 `vector_db` / `store` 二者须提供一个外，其余参数均为可选、默认关闭（等价纯向量检索）。提供 `get_relevant_messages(query, limit=5)` 语义检索方法。

### 3.4 `MemoryManager`

```python
MemoryManager(
    short_term: Memory,
    long_term: LongTermMemory | None = None,
    relevant_limit: int = 5,
    max_context_tokens: int | None = None,
    summarizer: Callable[[str], str] | None = None,
    system_budget_ratio: float = 1.0,
    compress_context: bool = False,
    profile_hook: ProfileHookFn | None = None,
)
```

主要方法：`add_message` / `build_context(query, relevant_limit=None)` / `end_session` / `clear` / `snapshot(model=None, metadata=None)` / `restore(snapshot)`。`MemoryManager` 不是 `Memory` 子类，但可经 `ReactAgent(memory=...)` 注入（`ReactAgent` 会识别并调用 `build_context`）。

## 4. 工具

| 名称 | 类型 | 作用 |
|---|---|---|
| `ToolRegistry` | 类 | 可实例化的工具注册表：封装工具名→实现映射、JSON Schema 列表与技能注册表，可经 `ReactAgent(tool_registry=...)` 注入实现工具/技能隔离 |
| `TOOL_REGISTRY` | 字典常量 | 默认注册表的工具名 → 实现函数视图（向后兼容，委托给模块级默认 `ToolRegistry`） |
| `TOOL_SCHEMAS` | 列表常量 | 默认注册表的 OpenAI tools JSON Schema 列表，传给模型（向后兼容） |
| `register_tool` | 函数 | 显式登记一个工具实现及其 JSON Schema（委托给默认注册表） |
| `call_tool` | 函数 | 根据工具名和参数调度执行工具，集中错误兜底（委托给默认注册表） |
| `build_tool_schema` | 函数 | 从函数签名 + docstring 自动推导工具的 JSON Schema |
| `set_skill_registry` | 函数 | 把技能注册表注入默认工具注册表（供 `load_skill` 解析；实例化路径用 `ToolRegistry.set_skill_registry`） |

```python
def register_tool(name: str, func: Callable[..., Any], schema: dict[str, Any]) -> None: ...
def call_tool(name: str, arguments: dict[str, Any]) -> Any: ...
def build_tool_schema(
    func: Callable[..., Any], description: str | None = None
) -> dict[str, Any]: ...
def set_skill_registry(registry: SkillRegistry) -> None: ...
```

- `register_tool`：schema 须含 `description` 与 `parameters` 键，且与函数签名同源；工具名重复抛 `ToolError`。
- `call_tool`：未知工具抛 `ToolNotFoundError`；执行异常包装为 `ToolError`（保留 `__cause__`）。
- `build_tool_schema`：辅助路径，生成结果可直接传给 `register_tool`；参数描述无法推导，需精细描述时建议手写。

内置工具（`gearlink.tools.builtin` 的 `get_current_time` 与 `gearlink.tools.load_skill` 的 `load_skill`）在导入 `gearlink` 时自动注册；`load_skill` 需显式 `import gearlink.tools.load_skill` 触发注册。

`ToolRegistry` 类（`gearlink/core/tool.py`）把工具注册表从进程级全局单例升级为可实例化组件：

```python
class ToolRegistry:
    def register_tool(
        self, name: str, func: Callable[..., Any], schema: dict[str, Any]
    ) -> None: ...
    def call_tool(self, name: str, arguments: dict[str, Any]) -> Any: ...
    def set_skill_registry(self, registry: SkillRegistry) -> None: ...
    def get_schemas(self, whitelist: list[str] | None = None) -> list[dict[str, Any]]: ...
    def unregister_tool(self, name: str) -> None: ...
```

- 每个实例独立维护工具集与技能集，经 `ReactAgent(tool_registry=...)` / `PlanExecuteAgent(tool_registry=...)` / `McpClient(tool_registry=...)` 注入，使同一进程内多个 Agent 持有隔离配置；未注入时使用模块级默认注册表（`TOOL_REGISTRY` / `TOOL_SCHEMAS` 为其视图，向后兼容）。
- `call_tool` 执行期间经 `contextvars` 把本实例注册为「当前注册表」，供 `load_skill` 等工具解析所属 Agent 的技能注册表，不再依赖全局状态。
- `unregister_tool` 按名注销工具（幂等），供 `McpClient.unregister_tools` 回滚使用。

## 5. 模型 Provider

| 名称 | 类型 | 作用 |
|---|---|---|
| `ModelProvider` | 抽象基类（ABC） | 模型提供者抽象：定义 `chat`（及默认回退非流式的 `chat_stream`）契约 |
| `ModelResponse` | dataclass | 模型响应的统一表示（`content` / `tool_calls` / `usage`） |
| `StreamChunk` | dataclass（frozen） | 流式响应中的单个事件（`delta` 增量文本 / `response` 完整响应） |
| `ToolCall` | dataclass | 模型返回的一次工具调用（`id` / `name` / `arguments`） |
| `TokenUsage` | dataclass | 单次模型调用的 token 用量（`input_tokens` / `output_tokens`） |
| `OpenAIProvider` | 类 | OpenAI 兼容接口提供者（适用于 OpenAI / DeepSeek / 国产兼容 base_url） |
| `OllamaProvider` | 类 | 本地 Ollama 提供者（继承 `OpenAIProvider`，无需密钥） |
| `AnthropicProvider` | 类 | Anthropic Claude 提供者（Messages API 双向归一化，依赖可选 `gearlink[anthropic]`） |

### 5.1 `ModelProvider`

```python
class ModelProvider(ABC):
    @abstractmethod
    def chat(
        self,
        messages: list[dict[str, Any]],
        tools: list[dict[str, Any]] | None = None,
        response_format: dict[str, Any] | None = None,
    ) -> ModelResponse: ...

    def chat_stream(
        self,
        messages: list[dict[str, Any]],
        tools: list[dict[str, Any]] | None = None,
        response_format: dict[str, Any] | None = None,
    ) -> Iterator[StreamChunk]: ...
```

- `chat`：发起一次对话，返回统一 `ModelResponse`。
- `chat_stream`：默认回退到非流式 `chat()`（一次性产出全文片段 + 终止事件）；具体提供者可覆写获得真流式，但须保证最后一个事件携带完整 `response`。

自定义 Provider 只需继承 `ModelProvider` 实现 `chat()`，返回 `ModelResponse`。

### 5.2 `OpenAIProvider`

```python
OpenAIProvider(
    model: str | None = None,
    api_key: str | None = None,
    base_url: str | None = None,
    timeout: float | None = None,
)
```

参数未传时依次回退环境变量再到默认值：`api_key` ← `DEEPSEEK_API_KEY`，`model` ← `DEEPSEEK_MODEL`（默认 `deepseek-v4-flash`），`base_url` ← `DEEPSEEK_BASE_URL`（默认 `https://api.deepseek.com`）。`timeout` 为请求超时秒数（`None` 时使用 SDK 默认值）；OpenAI SDK 内置重试已关闭（`max_retries=0`），重试由框架 `ReactAgent(max_retries=...)` 统一管理，避免双重重试。

### 5.3 `OllamaProvider`

```python
OllamaProvider(model: str | None = None, base_url: str | None = None, timeout: float | None = None)
```

默认模型 `qwen2.5:7b`，默认地址 `http://localhost:11434/v1`；环境变量回退 `OLLAMA_MODEL` / `OLLAMA_BASE_URL`。`timeout` 为请求超时秒数（`None` 时使用 SDK 默认值）。

### 5.4 `AnthropicProvider`

```python
AnthropicProvider(
    model: str | None = None,
    api_key: str | None = None,
    base_url: str | None = None,
    max_tokens: int = 4096,
)
```

环境变量回退 `ANTHROPIC_API_KEY` / `ANTHROPIC_MODEL` / `ANTHROPIC_BASE_URL`；未安装 `anthropic` 或缺少密钥时抛 `ValueError`。

## 6. MCP 外部工具

| 名称 | 类型 | 作用 |
|---|---|---|
| `McpClient` | 类 | 把一台外部 MCP 服务器的工具登记进本地工具注册表（命名为 `mcp_<server>_<tool>`，默认登记进模块级 `TOOL_REGISTRY`，可经 `tool_registry=` 注入指定实例），使 Agent 可无感知调用远端工具 |

```python
McpClient(server_name: str, session: Any, tool_registry: ToolRegistry | None = None)
client.register_tools()     # 拉取远端工具清单并登记，返回本地工具名列表
client.unregister_tools()   # 注销本客户端登记的全部工具（幂等）
```

`session` 为已完成 `initialize` 的 `mcp.ClientSession`（需 `pip install gearlink[mcp]`）。远端错误会归一化为文本作为工具结果交还模型，不抛异常中断循环。`tool_registry` 为工具注册表实例；`None` 时登记进模块级默认注册表（向后兼容）。注入后可与 `ReactAgent(tool_registry=...)` 配合实现工具隔离。

## 7. 技能

| 名称 | 类型 | 作用 |
|---|---|---|
| `Skill` | dataclass | 技能数据契约：L1 元数据（`name` / `description` / `metadata`）+ 按需加载的 L2 完整指令（`instructions`） |
| `SkillRegistry` | 类 | 技能内存注册表：显式注册、按名查询、列出全部 |
| `SkillLoader` | 类 | 技能文件系统加载器：从目录发现技能（仅 L1），按需加载完整指令（L2） |

```python
class SkillRegistry:
    def register(self, skill: Skill) -> None: ...
    def get(self, name: str) -> Skill: ...
    def list_all(self) -> list[Skill]: ...
    def contains(self, name: str) -> bool: ...


class SkillLoader:
    @staticmethod
    def discover_from_directory(base_dir: Path) -> list[Skill]: ...
    @staticmethod
    def load_full_instructions(skill: Skill) -> str: ...
```

技能名仅允许字母、数字与连字符；`get` 未命中抛 `SkillNotFoundError`；`discover_from_directory` 中单个技能解析失败仅警告跳过。

## 8. 可观测性

| 名称 | 类型 | 作用 |
|---|---|---|
| `TokenUsage` | dataclass | 单次模型调用 token 用量（`input_tokens` / `output_tokens` / `total_tokens`） |
| `UsageRecord` | dataclass | 单个标签下的累计用量（`input_tokens` / `output_tokens` / `calls`） |
| `UsageTracker` | dataclass | 按标签聚合多次调用用量，支持成本估算 |
| `JsonlEventSink` | 类 | 事件落盘器（见 §2） |
| `jsonl_hook` | 函数 | 构造事件落盘回调（见 §2） |
| `load_jsonl_events` | 函数 | 离线回放 JSONL 事件（见 §2） |

```python
class UsageTracker:
    def add(self, usage: TokenUsage | None, label: str = "default") -> None: ...
    def total(self) -> TokenUsage: ...
    def estimate_cost(self, prices: dict[str, tuple[float, float]]) -> float: ...
```

- `add`：累计一次调用用量（`usage` 为 `None` 时忽略）。
- `total`：全部标签的用量总和。
- `estimate_cost`：按「每千 token 单价」表估算成本；未收录的标签不计入。

## 9. 异常

| 名称 | 作用 |
|---|---|
| `GearLinkError` | 所有项目异常的基类 |
| `ProviderError` | 模型服务调用失败；`retryable` 属性标记瞬时故障（网络/限流/服务端错误），供 `max_retries` 决策 |
| `ToolError` | 工具注册/执行失败 |
| `ToolNotFoundError` | 请求的工具名未注册（`ToolError` 子类） |
| `MemoryError` | 记忆读写失败 |
| `SkillError` | 所有技能相关异常的基类 |
| `SkillNotFoundError` | 按名查找技能未命中 |
| `SkillLoadError` | 加载技能内容（如 SKILL.md 解析失败） |
| `SkillValidationError` | 技能元数据（YAML frontmatter）校验失败 |
| `SkillExecutionError` | 执行技能辅助脚本时出错 |

继承关系：

```
GearLinkError
├── ProviderError
├── ToolError
│   └── ToolNotFoundError
├── MemoryError
└── SkillError
    ├── SkillNotFoundError
    ├── SkillLoadError
    ├── SkillValidationError
    └── SkillExecutionError
```

公共 API 只抛出 `GearLinkError` 体系异常；捕获第三方异常后转换包装并保留 `__cause__`。工具执行失败在 ReAct 循环内属可恢复信号，以文本写回模型处理。

## 10. 日志开关

| 名称 | 类型 | 作用 |
|---|---|---|
| `enable_logging` | 函数 | 一键开启 `gearlink` 命名空间日志输出（stderr，级别可配置，幂等） |
| `disable_logging` | 函数 | 一键关闭 `gearlink` 命名空间日志输出（恢复静默，幂等） |

```python
enable_logging()  # 默认 INFO
enable_logging(logging.DEBUG)  # 指定更细级别
disable_logging()  # 关闭，恢复静默
```

框架默认静默；开启后框架日志统一经开关输出，不再向应用根日志器传播。

## 11. 工具函数

| 名称 | 类型 | 作用 |
|---|---|---|
| `estimate_tokens` | 函数 | 估算一段文本的 token 数（启发式：CJK 表意字符每字约 1 token，其余 4 字符/token） |

```python
def estimate_tokens(text: str) -> int: ...
def count_message_tokens(message: dict[str, Any]) -> int: ...
```

无网络与第三方依赖，用于上下文预算的近似分配；需要精确计数时可在应用层替换为 `tiktoken` 等专用实现。
