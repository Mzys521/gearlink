# 上下文处理升级方案

> 本文档定义本次「上下文处理」改进的详细实施方案，供审核后分阶段执行。
> 每完成一个阶段须向用户确认后再进入下一阶段；全部完成后同步更新项目文档。

## 1. 背景与目标

当前记忆体系已实现「短期滑窗 + 长期向量检索」的组合（`MemoryManager` 已落地），
但存在以下短板，本次按优先级分四阶段补齐：

| 短板 | 对应阶段 |
|---|---|
| 长期记忆只存原始消息，无会话级知识蒸馏 | 阶段二（2.1 会话摘要沉淀） |
| 长期记忆无限增长、检索不区分新旧 | 阶段二（2.3 时间衰减 + 容量上限） |
| 检索注入仅在每轮首迭代，不可配置 | 阶段二（2.2 检索时机可配置） |
| 演示入口不调用 `end_session`，摘要钩子空转 | 阶段二（2.1 配套） |
| `print` 日志、`MAX_ITERATIONS` 兜底无测试、文档过期 | 阶段一（规范补齐） |
| system 消息在预算裁剪中无上限、长期库内部去重缺失 | 阶段三（边界加固） |
| 文档与代码漂移 | 阶段四（文档同步） |

## 2. 设计约束（严格遵守既有规范）

1. **依赖倒置**（接口规范 §1.1 / 开发规范 §1）：`core/` 不得 import `providers/`。
   - 摘要生成通过注入 `Callable[[str], str]` 实现，具体模型调用由应用层（含 `__main__` 演示入口）组装。
2. **公共 API 只增不改**（接口规范 §6 / 架构设计 §8）：本次全部为新增可选参数，不破坏既有签名。
3. **构造参数注入**（接口规范 §7）：所有新配置通过构造参数传入，不引入隐式全局状态。
4. **跨模块数据用 dataclass / 标准类型**（接口规范 §3）：本次无需新增 dataclass，摘要使用 `str`。
5. **测试必须 mock 外部服务**（开发规范 §6）：摘要/检索相关测试全部使用 Fake 实现，不允许真实调用模型。
6. **风格与命名**（开发规范 §2/§3）：`ruff format` 行宽 100；测试命名 `test_<行为>_<场景>`。

## 3. 公共 API 变更总表（全部为纯新增，向后兼容）

| 类 | 新增参数 | 默认值 | 说明 |
|---|---|---|---|
| `MemoryManager.__init__` | `summarizer: Callable[[str], str] | None` | `None` | 会话摘要生成器，仅注入时启用摘要沉淀 |
| `MemoryManager.__init__` | `system_budget_ratio: float` | `1.0` | 非检索 system 消息占上下文预算的比例上限；`1.0` 表示不裁剪（现状） |

## 5. 阶段二：记忆机制升级

### 5.1 会话摘要沉淀（记忆巩固）

**设计**：`MemoryManager` 新增注入参数 `summarizer: Callable[[str], str] | None`。

- `end_session()` 时：
  1. 若 `summarizer` 为 `None` → 维持现状（仅清空短期，不新增逻辑）；
  2. 否则将短期记忆中的 user/assistant 文本拼成 transcript（格式 `用户: ...\n助手: ...`），调用 `summarizer(transcript)` 生成摘要；
  3. 摘要以 `role="assistant"`、content 前缀 `[会话摘要] ` 沉淀进长期记忆，`logger.info` 记录；
  4. 摘要生成抛异常时**不中断**会话结束：`logger.warning` 记录后继续原有补沉淀逻辑（核心层只做业务性容错，符合架构设计 §9）。
- 新增私有方法 `_build_transcript()` 负责拼接，便于测试。

**配套改动**（演示入口，`agent.py` 的 `__main__`）：
- `exit` 时调用 `memory.end_session()`；
- 组装一个基于 `OpenAIProvider` 的 summarizer lambda（内联摘要提示词）注入 `MemoryManager`——属应用层装配，不违反依赖倒置。

**新增测试**（`tests/test_memory_manager.py`，全部使用 fake summarizer）：
1. `test_end_session_sediments_summary_when_summarizer_set`——断言摘要（含 `[会话摘要]` 前缀）已进长期库，且 transcript 内容正确；
2. `test_end_session_without_summarizer_keeps_legacy_behavior`——无 summarizer 时行为与现状一致；
3. `test_end_session_ignores_summarizer_failure`——summarizer 抛异常时仍补沉淀、不抛错。

### 5.2 检索时机可配置

**设计**：`ReactAgent` 新增参数 `retrieve_every_iteration: bool = False`。

- [run()](file:///e:/opencoe/GearLink/gearlink/core/agent.py#L55-L57) 中 query 注入条件由 `iteration == 0` 改为 `iteration == 0 or self.retrieve_every_iteration`；
- 开启时依赖 `build_context` 的短期窗口去重避免重复注入（现状去重逻辑已存在，无需改动）；
- 更新 `__init__` 与 docstring。

**新增测试**（`tests/test_agent.py`）：
- `test_agent_retrieves_long_term_on_every_iteration_when_enabled`——`CapturingProvider` + 带 `LongTermMemory`(Fake) 的 `MemoryManager`，断言开启后第 2 次 `chat` 的消息仍含检索注入的 system 内容；未开启时第 2 次不含。

### 5.3 时间衰减 + 容量上限

**设计**：`LongTermMemory` 新增 `recency_weight: float = 0.0` 与 `max_entries: int | None = None`。

- **时间衰减**：`get_relevant_messages` 在 `recency_weight > 0` 时按 `score = distance + recency_weight * age_ratio` 排序，
  其中 `age_ratio = min((now - timestamp) / 30天, 1.0)`（归一化到 [0,1]，常量 `_RECENCY_NORM_SECONDS`）；
  排序后取前 `limit` 条。`recency_weight = 0` 时与现状完全一致。
- **容量上限**：`add_message` 写入后若超过 `max_entries`，按 timestamp 淘汰最旧的超出部分（`collection.delete`）；`None` 时不淘汰。
- 更新类 docstring。

**新增测试**（`tests/test_long_term_memory.py`）：
1. `test_get_relevant_messages_respects_recency_weight`——两条记录 distance 相同/不同、timestamp 一新一旧，断言 `recency_weight > 0` 时新记录排前；
2. `test_get_relevant_messages_default_order_unchanged`——默认 `recency_weight=0` 时排序与现状一致；
3. `test_add_message_evicts_oldest_over_max_entries`——`max_entries=3` 写入 5 条，断言仅剩最新 3 条。

## 6. 阶段三：边界加固

### 6.1 非检索 system 消息预算上限

**设计**：`MemoryManager` 新增 `system_budget_ratio: float = 1.0`。

- 检索注入的 system 消息已由 `_fit_retrieval_budget` 限制在预算的 25% 内（受保护）；
- 当 `system_budget_ratio < 1.0` 时，`build_context` 组装后对「受保护检索消息之外的 system 消息」执行
  新增私有方法 `_trim_system_to_ratio`：从最旧开始丢弃直至非检索 system 总 token 不超过 `预算 × system_budget_ratio`（保留最新一条，兜底不清空）；
- `1.0` 默认值下不调用该方法，现有测试零影响。

**新增测试**（`tests/test_memory_manager.py`）：
- `test_build_context_caps_system_prompts_when_ratio_set`——多条 system + `system_budget_ratio=0.5`，断言超出配额的最旧 system 被裁剪；
- 默认 `1.0` 行为由既有测试 `test_build_context_always_keeps_system_messages` 继续保障。

### 6.2 长期库内部去重

**设计**：分两层，均为新增能力。

1. **检索结果去重（默认开启，安全）**：`get_relevant_messages` 返回前按 content 精确去重、保留首个——现有测试数据内容均不同，不受影响；
2. **写入时去重（`dedupe: bool = False`，可选开启）**：`add_message` 在 metadata 中记录 `content_hash`（sha256），
   `dedupe=True` 时先按 `where={"content_hash": h}` 查询，命中则跳过并记 debug 日志（避免向量库同内容堆积）。

**新增测试**（`tests/test_long_term_memory.py`）：
1. `test_get_relevant_messages_dedupes_identical_content`——检索含重复 content 时只保留一条；
2. `test_add_message_with_dedupe_skips_duplicate_content`——`dedupe=True` 写同一内容两次仅存一条；
3. `test_add_message_without_dedupe_keeps_duplicates`——默认 `dedupe=False` 原样写入。

## 10. 风险与回退

- 全部改动均为新增可选参数，默认值等价现状 → 任何阶段可独立回退，不影响既有功能；
- `retrieve_every_iteration=True` 会增加 embedding 查询次数 → 明确为可选项，默认关闭；
- 摘要生成依赖注入的 summarizer → 未注入时功能完全降级为现状，不存在隐藏依赖。
