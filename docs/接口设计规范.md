# GearLink 接口设计规范

> 本文档定义 GearLink 作为开源库的 Python 公共 API 设计原则与扩展点约定。
> 任何新增或修改公共接口的 PR 必须符合本文档。

## 1. 总体原则

1. **依赖倒置**：`core/` 只面向抽象编程。Agent 依赖 `ModelProvider` 接口而非具体 SDK；上层通过构造函数注入实现。
2. **单一抽象入口**：每类扩展点只暴露一个抽象基类（如模型调用只有 `ModelProvider.chat`），实现者只需覆盖最少的方法。
3. **统一数据结构**：跨模块传递的数据一律使用本项目定义的 dataclass（如 `ModelResponse`、`ToolCall`），**不得让第三方 SDK 的类型（如 OpenAI 的响应对象）穿透到公共 API 边界之外**。
4. **显式优于隐式**：公共 API 不使用魔法方法、不做隐式全局状态注册；配置通过构造参数传入。
5. **最小公开面**：只有从 `__init__.py` 显式导出的名称才是公共 API；下划线前缀、未导出的一律视为内部实现，允许随时变更。

## 2. 抽象接口定义规范

以 `ModelProvider` 为模板，所有抽象接口须满足：

```python
class ModelProvider(ABC):
    """模型提供者抽象接口：屏蔽具体模型服务的调用细节"""

    @abstractmethod
    def chat(
        self, messages: list[dict[str, Any]], tools: list[ToolSchema] | None = None
    ) -> ModelResponse:
        """根据消息列表发起一次对话。

        Args:
            messages: OpenAI 消息格式的对话历史。
            tools: 可用工具的 schema 列表；None 表示不启用工具调用。

        Returns:
            ModelResponse: 统一响应结构，含文本内容与工具调用请求。

        Raises:
            ProviderError: 底层服务调用失败（网络、鉴权、限流等）。
        """
```

要求：

- 继承 `ABC` 并用 `@abstractmethod` 标注；docstring 必须写明契约（输入约束、返回保证、异常情况）。
- 参数尽量给出合理默认值，使最简实现只需必填最少参数。
- 接口一旦发布即冻结签名；确需变更时走第 6 节的废弃流程。

## 3. 数据结构规范

- 跨模块数据载体一律用 `dataclass`（必要时 `frozen=True`），字段全部带类型标注。
- 字段命名与业界通行格式对齐：工具调用沿用 `id / name / arguments`，消息沿用 `role / content / tool_calls / tool_call_id`。
- 需要序列化的结构（写入记忆、持久化）须提供 `to_dict()` / `from_dict()` 方法对，且保证往返一致。
- 不得用裸 `dict` 承载本项目自创概念（如工具调用结果）；OpenAI 消息格式等既有标准除外。

## 4. 扩展点设计（插件契约）

GearLink 有四类扩展点，均遵循「注册表 + schema + 调度器」三件套模式（参考 `core/tool.py`）：

| 扩展点 | 位置 | 契约 |
|---|---|---|
| Provider | `providers/` | 继承 `ModelProvider`，实现 `chat` |
| Tool | `tools/` | 普通函数 + JSON Schema 描述，注册进 `TOOL_REGISTRY` |
| Skill | `skills/` | 待定（发布前补齐） |
| Memory | `core/memory.py` | 继承 `Memory`，实现 `add_message` / `get_messages` / `clear` |

Memory 扩展点补充说明：`MemoryManager` 是面向「短期 + 长期」场景的内置组合器，**不是 `Memory` 子类**——它不对齐三方法抽象签名，而是提供 `build_context` / `end_session` 等专用接口（见 `架构设计.md` §6）。自定义组合逻辑时可参考其实现，也可直接组合任意 `Memory` 实现。

记忆升级（架构设计 §8 步骤 8）新增的可选构造参数——**全部为可选，默认值等价现状，向后兼容**：

- `MemoryManager(summarizer=..., system_budget_ratio=...)`：
  - `summarizer: Callable[[str], str] | None`——会话摘要生成器，`end_session` 时把会话文本拼成 transcript 交由它生成摘要沉淀进长期记忆；由应用层注入（依赖倒置，`core/` 不依赖 `providers/`）；
  - `system_budget_ratio: float`——非检索 system 消息占上下文预算的比例上限，检索注入消息受 `RETRIEVAL_BUDGET_RATIO` 独立保护。
- `LongTermMemory(recency_weight=..., max_entries=..., dedupe=...)`：检索排序时间衰减权重、容量上限（超限淘汰最旧条目）、写入前按 content sha256 哈希去重开关。
- `ReactAgent(retrieve_every_iteration=...)`：每轮 ReAct 迭代是否携带查询注入长期记忆；`False` 表示仅首轮注入（现状）。

通用规则：

- **注册表显式声明**：`TOOL_REGISTRY: dict[str, Callable]` 形式，key 为唯一名称，禁止运行时隐式扫描。
- **schema 与实现同源**：工具的 JSON Schema 必须与函数签名严格一致，新增/修改工具时两者同步更新。
- **调度器集中错误处理**：调用方（如 `call_tool`）负责未知名称、参数解析、执行异常的统一兜底，实现函数本身无需防御性包装。
- 第三方贡献的扩展不得修改 `core/`，只能新增文件并注册。

## 5. 错误处理规范

建立统一异常层次，发布前于 `gearlink/exceptions.py` 集中定义：

```
GearLinkError            # 所有项目异常的基类
├── ProviderError        # 模型服务调用失败
├── ToolError            # 工具注册/执行失败
│   └── ToolNotFoundError
└── MemoryError          # 记忆读写失败
```

规则：

- 公共 API 只抛出 `GearLinkError` 体系的异常；捕获第三方异常后须转换包装，保留 `__cause__`。
- 工具执行失败在 ReAct 循环内属于**可恢复信号**：以文本结果写回消息交给模型处理，不得直接中断（现状 `agent.py` 已符合）。
- 异常消息面向开发者，包含足够定位信息（工具名、模型名等），不泄露密钥。

## 6. 兼容性与废弃流程

- 遵循语义化版本：破坏性公共 API 变更只能在 MAJOR 版本发布。
- 废弃流程（至少跨一个 MINOR 版本）：
  1. 新版本中保留旧接口，标注 `@deprecated` 并发出 `DeprecationWarning`；
  2. docstring 注明替代方案与计划移除版本；
  3. CHANGELOG 的 `Deprecated` 段落记录；
  4. 下一个 MAJOR 版本移除。
- 内部 API（未导出/下划线前缀）不受此约束。

## 7. 命名与签名惯例

- 工厂/构造函数注入依赖：`ReactAgent(provider=...)`、`MemoryManager(short_term=..., long_term=...)`，参数名与抽象类型对应。
- 获取类方法用 `get_*`（可返回 None 用 `get_*_or_none` 或文档说明），动作类用动词（`run`、`call_tool`、`add_message`）。
- 布尔参数数量 ≥ 2 个时改为枚举或拆分方法，避免 `f(True, False)` 式调用。
- 公共函数禁止使用 `*args` / `**kwargs` 透传（装饰器等特殊场景除外并说明）。

## 8. 文档与示例要求

每个公共 API 须具备：

1. 完整类型标注 + Google 风格 docstring（含 Args / Returns / Raises）；
2. `examples/` 中至少一个可直接运行的示例；
3. `tests/` 中覆盖正常路径与至少一个异常路径的用例。

三者缺其一，PR 不予合入。
